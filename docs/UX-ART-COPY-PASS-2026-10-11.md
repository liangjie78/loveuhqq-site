## 1. 年历 ↔ 日子背面 ↔ 里程碑一条线

### 问题
- 点年历格子已能打开日子背面（`journal:date` → notebook）。
- 「记下的日子」票根（`MomentArchive.astro`）**无点击**，与年历/背面未接通。
- 里程碑日（如 07.01、10.08）在年历上已涂色，背面却常显示「这一天还空着」/ 写过 0，叙事断裂。
- 信封旁静态句「解锁共同手账后，才能读到信里的文字。」登录后仍显示（`index.astro` 约 L172）。

### 行为规格
1. **票根可点**：每个 `Moment` 票根为可聚焦控件（button 或等价）。点击后：
   - 选中对应 `date`（与点年历格子同一套 `pick` / `journal:date` 路径）；
   - 若该日不在当前可见年网格，先切到正确年份再选中；
   - `scrollIntoView` 到 `.day-back`（日子背面），并 `renderNote()`；
   - 视觉：票根 `aria-current` / 选中态与年历当天一致。
2. **里程碑日与空状态**：
   - 若该日在 `moments.ts` 有标题，且笔记为空：背面主文案改为「这一天我们记下了：**{title}**。」副文可保留「想写一句的时候，再写。」不要只显示「这一天还空着。」
   - 「翻看写过的日子」计数仍只统计真正有笔记的日子；可选在列表中把里程碑日单独标出（有笔记 / 仅里程碑），但不要把无笔记里程碑算进「写过」。
3. **已解锁：去掉「请先解锁」感**：
   - `index.astro` 信封旁静态「解锁共同手账后…」→ 仅在未登录时渲染；已登录隐藏或改为「拆开信封，读这封写给第 100 天的信。」
   - `gallery.ts`：已登录且 `featured` 为空时，不要继续展示「待解锁」占位文案；改为「留给下一张」类空位（与相册贴图空位语气一致）。
   - `PhotosLocked` 在已登录加载成功后保持 hidden（现状应已如此，回归测一下）。

### 验收
- [ ] 点任一票根 → 年历选中该日 + 背面展示该日（含里程碑标题兜底）。
- [ ] 07.01 / 10.08 等里程碑日空白记时，不再只显示「还空着」。
- [ ] 已登录后信封旁与首页照片墙不再出现解锁提示 /「待解锁」。

## 2. 照片可见性

### 问题
首页/相册缩略图发白、灯箱像淡叠影、深色游戏截图与纸感冲突。源码无单独「发白」prop，观感来自 `global.css` 纸底 + `saturate(.9)` + 裁切。

### 规格
1. **缩略图**：`.polaroid img` / `.polaroid-private img`
   - 保证 `opacity: 1`（无额外压透明）；避免过强 `filter` 导致发灰发白。可保留轻微 `contrast`，`saturate` 不低于 `0.95` 或不加 desaturate。
   - 背景：浅色内容用 `--paper-2`；**深色截图**（可用简单亮度启发，或给 manifest 可选 `tone: "dark"`）使用深色衬底（如 `#1a1412` 或 `--ink` 低透明），避免纸色透过造成「发白」。
2. **灯箱**：`.lightbox-print img`
   - 打开后主体为一张可读大图（足够对比、不被底下格子透出干扰）。
   - 遮罩足够不透；图面完整可见（优先完整展示，必要时 letterbox，不要只留淡影）。
   - 深色图同样用深色衬底。
3. **不要**改私密上传流程；本 pass 只改呈现。

### 验收
- [ ] 首页 featured 与 `/photos/` 缩略图内容清晰可读，无大片发白。
- [ ] 灯箱内可看清主体；关闭后回到墙。
- [ ] 至少一张深色游戏/聊天截图在墙与灯箱下都不「糊进纸里」。

### 对准文件
`src/styles/global.css` · `src/scripts/gallery.ts` · `src/components/Lightbox.astro`

## 3. 年历对比度 + 手机第一屏 + 顶栏收紧

### 规格
1. **年历对比度**（`global.css` tokens / `.year-cells`）
   - 「未到」格与纸色对比可辨（提高 `--empty` 相对 `--paper` 的对比，目标约能辨认格子边界）。
   - 「走过 / 今天 / 纪念日」三态色差拉开；纪念日未到与已走过不要几乎同色。
2. **手机第一屏（≤640 / ≤380）**
   - 进入 `#days` 时，优先看到年历格子 +「今天」反馈，而不是被空的「日子的背面」大卡片盖住整段。
   - `.year-feedback` sticky 不要在窄屏上长期挡住大半格子；可降低 sticky 侵略性或调整背面默认折叠高度。
3. **顶栏**
   - `SiteHeader`：窄屏尽量单行（站点名 + 身份/退出 + 导航），避免折成两行再挤出大片空白导致英雄区心/标题滚出第一屏。
   - `--header` 高度与 `hero` / sticky 计算一致。

### 验收
- [ ] 桌面与手机上能分辨：未到 / 走过 / 今天 / 纪念日。
- [ ] iPhone 宽约 390：打开首页滚到「日子」时，格子与今天可见。
- [ ] 窄屏顶栏不再稳定折成两行占高；英雄区主视觉更易进首屏。

### 对准文件
`src/styles/global.css` · `src/styles/notebook.css` · `src/components/SiteHeader.astro` · `src/pages/index.astro`（仅当必须微调区块顺序；优先 CSS）

## 4. 文案破功处（手账口吻）

只改破功与系统句，不重写整站气质。

### 必须
| 位置 | 现状 → 目标 |
|---|---|
| `index.astro` 信封旁 | 见 §1：未登录保留提示；已登录改为手账句或隐藏 |
| `SiteHeader.astro`「已解锁」 | → 「手账已打开」或「我们的手账」（短、纸感） |
| `FutureList.astro`「清单将保存在云端实时同步」 | → 「写进手账里，换个地方也能接着看。」 |
| `Notebook.astro`「手账保存在云端…」等加载/说明 | 去掉「云端」字样，改为「本子」「手账」口吻（保留功能含义） |
| `notebook.ts` toast「收好了，云端已保存。」等 | 「收好了。」/「先放进手账里了。」；错误句可保留「暂时连不上」但少说「云端」 |
| `letter.ts`「登录已失效，请重新解锁后拆信。」 | → 「钥匙好像过期了，再打开一次手账再拆信。」 |

### 建议（若正文在仓库初稿）
- `worker/letter.ts` 初稿：`来的意外的快` → `来得意外的快`；日期风格与站内 `2026.07.01` 对齐。
- **正式 KV 正文**勿擅自改；列给用户授权后再改（见内容清单）。

### 验收
- [ ] 已登录主路径无「请先解锁 / 云端实时同步」类后台口吻。
- [ ] 顶栏身份文案是手账语气。
- [ ] 不扩大到重写所有营销句。

## 内容运营清单（Creative Designer 列，不擅自上传）

### A. 正式百日信
- [ ] 用户确认 KV 定稿（ salutation / paragraphs / closing ）
- [ ] 校对：来得、日期格式、去掉过出口语若需对外访客可见
- [ ] 授权后：`.private-letter/hundred-day.json` + `scripts/upload-letter.mjs`（或现有流程）

### B. 精选三张（首页 featured）
- [ ] 用户指定 3 张（建议：一张两人/纪念、一张日常、一张「一起听歌」或软时刻）
- [ ] 每张：标题（手账口吻，外人可读的主标题 + 可选小字内部梗）、拍摄日期 `YYYY-MM-DD`、是否深色截图
- [ ] 授权后走现有照片上传 / manifest 更新

### C. 补纪念日节点（`src/data/moments.ts`）
建议核对是否已有；缺则补（需用户确认文案）：
- `2026-05-27` 通过游戏认识（若叙事要公开）
- `2026-07-01` 第一天（应已有）
- `2026-09-06` 抖音火花 100 天（若保留）
- `2026-10-08` 恋爱 100 天（应已有）
- 可选：第一次一起听歌日 `2026-06-24`（若要从照片升为票根）

**素材要求**：日期准确、标题 ≤12 字为宜、与年历起点叙事一致（0701 起算 vs 更早认识 —— 若保留 05.27，票根点击后背面应用里程碑兜底文案说清）。
