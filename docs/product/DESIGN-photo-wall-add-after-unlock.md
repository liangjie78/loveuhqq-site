# 设计说明：解锁后可在照片墙「贴一张」

> 状态：**设计说明 · v1.0 · 对齐 PRD v1.0 + 产品确认结论 · 实现依据** · 2026-10-11（Asia/Shanghai）  
> 仓库：`/workspace/loveuhqq-site`  
> 起草：产品设计（Leo Park）  
> 对齐需求：`docs/product/PRD-photo-wall-add-after-unlock.md`（定稿 v1.0）  
> 对齐视觉：`docs/DESIGN.md`（纸上手账）  
> 说明：可指导工程实现。开放项已按 PRD v1.0 与产品确认结论（§7）收口；与 PRD 冲突时以 PRD 为准（本组无冲突）。不改业务代码。

## 1. 设计目标与约束

### 1.1 目标

在共同密码解锁、会话有效时，让两人能在相册页把新照片「贴」进私密照片墙——选图、写标题、可选日期——成功后立刻出现在拍立得墙上，感受与「往后」清单、「写一句」日记同属一本共同手账，而不是后台管理系统。

### 1.2 体验原则

| 原则 | 落地 |
| --- | --- |
| 像贴实物，不像上传后台 | 入口仍是墙上的虚线拍立得空位；流程用纸面卡片，不用侧栏抽屉或设置页 |
| 口语、克制 | 按钮与状态沿用手账语气；不写矫情情话，不编造经历 |
| 仅解锁可见 | 未解锁 / 会话失效：无添加入口、无私密 DOM；与现有 `clearPhotos` 一致 |
| 本期只做添加 | 不设计删图、改标题、精选管理 UI（PRD Out） |
| 不动首页构图 | 首页三张精选墙不放添加入口（PRD 已定） |

### 1.3 视觉与实现约束（来自 DESIGN.md / 源码 / PRD）

- **纸上手账语言**：暖色纸面 `#f5eee4`、贴纸 `#fffcf7`、墨色 `#2a1f1b`、辅助 `#76645b`、蜡封红 `#b0474f`；标题用宋体，界面小字与私密标题用系统无衬线；胶带锯齿边、拍立得白边、多层纸影。
- **刻意回避**：渐变、毛玻璃、英文眉标、大面积模糊、章节页码式导航。
- **可点目标** ≥ 44px（日历格除外）；焦点描边用蜡封红。
- **减少动态效果**：关闭动画后流程仍可完成；上传中用文案而非依赖动效。
- **数据形状**：标题必填、≤80 字；日期可选 `YYYY-MM-DD`；排序仍按拍摄日期（无日期靠后）；新图默认不进首页 `featured`。
- **压图与限额（对齐 PRD §5.E / §7 第 6 条）**：客户端生成去 EXIF 的 WebP；thumb 约 800×1000 inside；large 最长边 ≤1800。KV **单值 ≤25MB**；清单约 **≤2000** 张。接近上限时有可读失败提示（文案工程可草案）。更细请求体硬顶由工程在实现时定。

## 2. 信息架构与界面层级

```
相册页 /photos/（已解锁）
├── 页眉 SiteHeader（已解锁 / 退出）
├── album-head：标题「相册」+ 摘要「N 张我们的照片。」
├── album-wall（data-photo-wall="all"）
│   ├── 真实拍立得 × N（可点开灯箱）
│   └── 【贴一张】入口 ← 由原装饰空位「留给下一张」升级
├── （可选）photos-status 状态行（加载相册 / 上传失败等）
└── 贴图面板 dialog（点入口后打开）
    ├── 预览区（拍立得比例虚线框 / 选中后缩略图）
    ├── 标题（必填）
    ├── 拍摄日期（可选）
    └── 操作：取消 · 贴上
```

**层级关系**

1. **墙面入口**：始终在相册墙末尾；与真实拍立得同属一格网格，视觉上是「下一张空位」，交互上是唯一添加入口。
2. **贴图流程**：原生 `dialog` 纸面卡片盖在相册上（遮罩用现有 `--backdrop`，对齐灯箱 / 百日信弹窗）；关闭后焦点回到入口。
3. **成功 / 失败反馈**：成功以墙刷新为主（摘要张数 +1、新卡插入排序位置、末尾入口仍在）；失败留在面板内可重试，或关闭后面板消失、入口旁用 status 提示。

**不在本期出现的层级**：首页精选墙添加入口、相册管理菜单、精选勾选、删除/改名面板。

### 3.2 已解锁墙面：「贴一张」相对「留给下一张」

**定稿方案**：末尾空位从装饰 `div[aria-hidden]` 升级为可点的 **button**；**主文案「贴一张」**，辅文案「留给下一张」（小字，保留手账语气）。面板标题与 aria 用「贴一张照片」；提交按钮「贴上」。对齐产品确认结论 §7 第 7 条。

```
桌面 · album-wall 三列（示意）

  ┌─拍立得─┐     ┌─拍立得─┐     ┌─拍立得─┐
  │  [胶带] │     │  [胶带] │     │  [胶带] │
  │  照片A  │     │  照片B  │     │  照片C  │
  │ 标题 ·日期│    │ 标题 ·日期│    │ 标题 ·日期│
  └────────┘     └────────┘     └────────┘
        ↘ 微倾          ↗ 错落

  ┌─拍立得─┐     ┌─拍立得─┐     ┌════════════╗
  │  照片D  │     │  照片E  │     ║ 虚线空位    ║
  │ 标题 ·日期│    │ 标题 ·日期│    ║            ║
  └────────┘     └────────┘     ║  贴一张     ║  ← 可聚焦按钮（主文案）
                                 ║ 留给下一张  ║     （辅；蜡封红描边 focus）
                                 ║            ║
                                 ╚════════════╝
```

**与现状差异**

| | 现状 `emptySlot()` | 本设计（v1.0） |
| --- | --- | --- |
| 角色 | 装饰空位 | 添加入口 |
| 文案 | 「留给下一张」居中 | **主：「贴一张」**；辅：「留给下一张」 |
| 语义 | `div` + `aria-hidden` | `button type="button"`，`aria-label="贴一张照片"` |
| 悬停 | 无 | 虚线略加深 / 文案转蜡封红（对齐 `pencil-button:hover`），**不**抬起成实心拍立得 |
| 点击 | 无 | 打开贴图面板 |

**手机（≤720px，两列）**：末尾入口仍占一格；点击区整卡 ≥ 44px 高；主文案「贴一张」不换行。

```
  ┌────┐  ┌────┐
  │照片│  │照片│
  └────┘  └────┘
  ┌────┐  ╔════╗
  │照片│  ║贴一张║
  └────┘  ╚════╝
```

### 3.3 贴图表单 / 面板（纸面 dialog）

对齐门禁卡片宽度感（约 `min(100%, 24rem)`）与百日信 `letter-dialog` 的纸面 + 遮罩关闭 + Esc；**不用**毛玻璃。顶部可轻贴一条米色胶带装饰（`tape`，`aria-hidden`）。

```
              （遮罩 · 点遮罩关闭，等同取消）
    ┌──────────────────────────────────┐
    │            ≡ 胶带 ≡               │
    │                                  │
    │         贴一张照片                │  ← 宋体标题
    │                                  │
    │   ┌──────虚线拍立得框──────┐     │
    │   │                        │     │
    │   │     点这里选一张图      │     │  ← 未选：虚线 + 口语提示
    │   │     或「从相册选」      │     │     整区可点 → 隐藏 file input
    │   │                        │     │
    │   └────────────────────────┘     │
    │                                  │
    │   标题                            │
    │   ___________________________    │  ← 底边虚线输入（对齐 wish-form）
    │   （默认：文件名去扩展名）         │
    │                                  │
    │   拍摄日期（可选）                 │
    │   [ 2026-10-11        ] 📅       │  ← type=date；可清空
    │                                  │
    │   [ 取消 ]          [ 贴上 ]      │  ← text-button · pencil-button
    │                                  │
    │   （错误时）这张暂时贴不上，再试一次。│
    └──────────────────────────────────┘
```

**已选图后的预览区**

```
    │   ┌──────拍立得预览───────┐     │
    │   │  [缩略图，原始比例，   │     │
    │   │   过高则顶部截取]      │     │
    │   └───────────────────────┘     │
    │   [ 换一张 ]                     │  ← text-button，重新打开文件选择
```

**字段规则（对齐 `photos.ts`）**

- 标题：必填；`maxlength=80`；trim 后为空不可提交；占位「给这张写个名字」。
- 日期：可选；有则角标显示为点分格式（现有 `dotted()`）；无则排在无日期组。
- 默认标题：选图后用文件名去掉扩展名填入（可改）；若文件名不可用则留空并聚焦标题框。
- 默认日期：【设计默认】若客户端能从选中文件读到拍摄日（对齐 prepare 的 EXIF 日），则预填；读不到则空。用户可改可清。工程实现时确认浏览器端 EXIF 能力；读不到不阻塞流程。

### 3.5 成功态

- **主反馈**：关闭面板 → 墙 `render` 刷新 → 新拍立得出现在按日期排序后的位置 → 摘要变为「N+1 张我们的照片。」→ 末尾「贴一张」入口仍在。
- **成功提示**：【设计默认】**不要**「贴好了。」toast；墙刷新 + 摘要 +1 即反馈（对齐 §7 第 8 条）。
- 焦点：回到墙上新拍立得，或回到「贴一张」入口（实现二选一；推荐回到新卡，方便立刻开灯箱确认）。

### 3.6 错误态

**面板内（推荐，选图后提交失败）**

```
    │   …表单保持已填内容…              │
    │   这张暂时贴不上，再试一次。       │  ← 蜡封红小字，对齐 gate-error
    │   [ 取消 ]              [ 再试一次 ]│
```

**入口旁（面板已关 / 会话 401）**

- 复用 `.photos-status` +「再试一次」模式（现有加载相册失败样式）。
- 401：走现有 `clearPhotos` + 会话失效；添加入口随墙恢复为锁定空位而消失。

**校验（提交前，不发请求）**

- 未选图：「先选一张图再贴。」
- 标题空：「给这张写个名字再贴。」（`setCustomValidity` / 面板内提示，对齐清单「写下一件小事再收好。」）
- 类型不符（非图片）：「换一张照片试试。」（jpg/png/webp/heic 等以工程最终白名单为准）
- 接近清单上限（约 2000）或单值超限（≤25MB）：可读失败提示（工程可草案，产品可再润色）。

## 4. 关键交互流程（≤5 步主路径）

```
① 已解锁用户在 /photos/ 点击墙末「贴一张」
        ↓
② 打开贴图面板 → 点预览区选本地图（系统文件/相册）
        ↓
③ 确认或改标题；可选填/改拍摄日期
        ↓
④ 点「贴上」→ 客户端压图去 EXIF → 鉴权上传
        ↓
⑤ 成功：面板关闭，墙上出现新拍立得，摘要 +1
```

### 4.1 分支与边界

| 步骤 | 分支 | 行为 |
| --- | --- | --- |
| ① | 未解锁 / 无会话 | 入口不存在；访客只能「解锁照片」 |
| ① | 首页精选墙 | 无入口（本期已定） |
| ② | 取消文件选择 | 面板保持打开，预览仍为空 |
| ② | 换一张 | 【设计默认】**不覆盖**用户已手改的标题（记脏标记）；未手改则可随新文件名更新。日期：能读 EXIF 则预填，不能则空（用户可改） |
| ③ | Esc / 取消 / 点遮罩 | 关闭面板，不上传；焦点回入口 |
| ④ | 上传中退出/会话撤销 | 中止请求；`clearPhotos`；面板强制关闭 |
| ④ | 网络失败 | 面板内错误 +「再试一次」；不写半成品清单（工程事务/回滚） |
| ⑤ | 排序 | 有日期按日插入；无日期靠后；末尾入口始终最后一格 |
| ⑤ | 灯箱 | 新卡可点，行为与现有 `polaroid-private` 一致 |

### 4.2 与现有脚本的衔接（给实现，非改码）

- 入口生成：替代 / 扩展 `gallery.ts` 的 `emptySlot()`，仅 `data-photo-wall="all"` 的墙追加可点入口。
- 刷新：上传成功后重新 `parsePhotoManifest` + `render`，或乐观插入后再拉清单（工程定）；须更新 `data-photos-summary`（`photoSummary`）。
- 会话：`onSessionChange` / `pagehide` / 退出捕获点击时，关闭贴图 dialog 并清空已选文件与预览 blob URL。

## 5. 视觉与文案建议

### 5.1 视觉

| 元素 | 建议 |
| --- | --- |
| 入口空位 | 沿用 `.polaroid-empty`：透明底、`1.5px dashed var(--line-strong)`；可点后 `cursor:pointer`；hover 文案色 `--rose`，outline 略用 `--line-stronger` |

| 次按钮 | `.text-button`「取消」「换一张」「再试一次」 |

| 遮罩 | 现有 `--backdrop`；**禁止** backdrop-filter 毛玻璃 |

## 6. 状态与边界一览

| 状态 | 入口 | 面板 | 墙 |
| --- | --- | --- | --- |
| 未解锁 | 不可见（锁定占位「待解锁」） | 无 | 占位 |
| 已解锁 · 闲置 | 「贴一张」在末尾（辅「留给下一张」） | 关 | 真图 + 入口 |
| 选图 / 填表 | 仍在墙后 | 开，可编辑 | 不变 |
| 上传中 | 可被会话清空逻辑拆掉 | 字段禁用；可取消 | 不变直至成功 |
| 成功 | 保留在新列表末尾 | 关 | 新卡出现，摘要 +1 |
| 失败 | 在 | 开，错误文案 + 重试 | 不变 |
| 取消 / Esc | 在，重获焦点 | 关，丢弃未提交选择 | 不变 |
| 退出 / 跨标签撤销 / bfcache | 随 `clearPhotos` 消失 | 强制关并丢弃 | 恢复锁定空位 |
| 减少动效 | 同闲置 | 无 print-in 动画，直接显示 | 同 |
| 无 JS | 无入口（与现私密能力一致） | — | 静态占位 |

### 6.1 移动端注意

- 文件选择：`input[type=file] accept="image/*"`；部分 Android 需用户手势直接触发，预览区点击即可，避免额外确认层拦截。
- 面板：小屏全宽留边距 `var(--gutter)`；长表单时面板内部滚动，标题与关闭/取消仍可见（对齐百日信「手机长文只在正文区滚动」）。
- 日期：原生 `input[type=date]`；iOS 上注意 16px 防缩放（门禁隐藏 input 已用 16px）。
- 横屏：面板最大高度 `min(90dvh, …)`，避免被键盘顶出视口时丢失主按钮。

### 6.2 无障碍

- 入口：真实 `button`，可见焦点蜡封红描边；`aria-label="贴一张照片"`。
- 面板：`dialog` + 标题关联；打开时焦点进面板（选图按钮或标题框）；关闭回入口。
- 状态：`role="status"` 播报上传中 / 失败。
- 装饰胶带、虚线框装饰对辅助技术隐藏或由按钮名覆盖。
